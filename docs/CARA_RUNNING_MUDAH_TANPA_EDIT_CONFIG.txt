CARA RUNNING MUDAH TANPA EDIT CONFIG BERKALI-KALI
=================================================

Tujuan perubahan ini:
- config.env cukup dipakai sebagai default awal.
- Saat pengujian, tidak perlu bolak-balik ubah RUN_ID dan SCENARIO.
- Setiap skenario dijalankan dengan parameter command.
- Bisa juga menjalankan semua dari satu terminal PowerShell menggunakan SSH.

Contoh IP:
- Ubuntu Server A / Broker   : 192.168.56.10
- Ubuntu Server B / Attacker : 192.168.56.20
- Windows Client             : 192.168.56.1

Kalau IP broker berbeda, ganti 192.168.56.10 pada command.


1. SETUP SEKALI SAJA
-------------------

Windows:

cd butnowismqttbtw\01_windows_client
Copy-Item config.env.example config.env
py -3 -m pip install -r requirements.txt

Ubuntu Server A:

cd ~/butnowismqttbtw/02_ubuntu_server_a_broker
cp config.env.example config.env
chmod +x scripts/*.sh
ip -br address

Catat nama interface yang punya IP broker.
Contoh: enp0s8.

Ubuntu Server B:

cd ~/butnowismqttbtw/03_ubuntu_server_b_attacker
cp config.env.example config.env
chmod +x scripts/*.sh


2. SKENARIO NORMAL
------------------

Gunakan RUN_ID yang sama pada Windows dan Server A.
Contoh: normal_01.

Ubuntu Server A:

./scripts/run_broker.sh --scenario normal --run-id normal_01 --broker-host 192.168.56.10 --iface enp0s8 --duration 60 --capture-duration 75

Windows:

powershell -ExecutionPolicy Bypass -File .\run_client.ps1 -Scenario normal -RunId normal_01 -BrokerHost 192.168.56.10 -Duration 60

Ubuntu Server B tidak perlu menjalankan serangan untuk skenario normal.


2B. CARA PALING MUDAH: SATU TERMINAL POWERSHELL
-----------------------------------------------

Syarat:
- Windows sudah bisa SSH ke Ubuntu Server A.
- Windows sudah bisa SSH ke Ubuntu Server B.
- Mosquitto sudah aktif di Ubuntu Server A.
- Project sudah dipull pada Windows, Server A, dan Server B.
- Jika belum memakai SSH key, PowerShell akan meminta password SSH.
- Saat capture/attack dimulai, PowerShell akan meminta password sudo Ubuntu.
- Tidak perlu tekan Ctrl+C. Capture akan berhenti sendiri sesuai -CaptureDuration.
- Setelah selesai, file hasil Server A dan Server B otomatis dicopy ke folder
  experiments\<RUN_ID>\ pada Windows.

Dari Windows:

cd butnowismqttbtw\01_windows_client

Normal:

powershell -ExecutionPolicy Bypass -File .\run_experiment.ps1 -Scenario normal -RunId normal_01 -BrokerHost 192.168.56.10 -ServerAUser server-a -ServerBUser server-b -BrokerIface enp0s8

SYN flood:

powershell -ExecutionPolicy Bypass -File .\run_experiment.ps1 -Scenario syn_flood -RunId attack_01 -BrokerHost 192.168.56.10 -ServerAUser server-a -ServerBUser server-b -BrokerIface enp0s8 -AttackRate 1000

Rate limiting:

powershell -ExecutionPolicy Bypass -File .\run_experiment.ps1 -Scenario syn_flood_rate_limit -RunId mitigation_01 -BrokerHost 192.168.56.10 -ServerAUser server-a -ServerBUser server-b -BrokerIface enp0s8 -AttackRate 1000

Kalau username Ubuntu berbeda, ubah -ServerAUser dan -ServerBUser.
Kalau path project di Ubuntu berbeda, tambahkan:

-ServerAProject "~/mqtitit/02_ubuntu_server_a_broker"
-ServerBProject "~/mqtitit/03_ubuntu_server_b_attacker"


3. SKENARIO SYN FLOOD
---------------------

Gunakan RUN_ID yang sama pada ketiga mesin.
Contoh: attack_01.

Ubuntu Server A:

./scripts/run_broker.sh --scenario syn_flood --run-id attack_01 --broker-host 192.168.56.10 --iface enp0s8 --duration 60 --capture-duration 75

Windows:

powershell -ExecutionPolicy Bypass -File .\run_client.ps1 -Scenario syn_flood -RunId attack_01 -BrokerHost 192.168.56.10 -Duration 60

Ubuntu Server B:

./scripts/run_attacker.sh --scenario syn_flood --run-id attack_01 --broker-host 192.168.56.10 --duration 60 --attack-rate 1000 --yes-local


4. SKENARIO RATE LIMITING
-------------------------

Gunakan RUN_ID yang sama pada ketiga mesin.
Contoh: mitigation_01.

Ubuntu Server A:

./scripts/run_broker.sh --scenario syn_flood_rate_limit --run-id mitigation_01 --broker-host 192.168.56.10 --iface enp0s8 --duration 60 --capture-duration 75

Windows:

powershell -ExecutionPolicy Bypass -File .\run_client.ps1 -Scenario syn_flood_rate_limit -RunId mitigation_01 -BrokerHost 192.168.56.10 -Duration 60

Ubuntu Server B:

./scripts/run_attacker.sh --scenario syn_flood_rate_limit --run-id mitigation_01 --broker-host 192.168.56.10 --duration 60 --attack-rate 1000 --yes-local


5. URUTAN JALAN YANG BENAR
--------------------------

Untuk setiap skenario:

1. Jalankan Server A dulu.
2. Jalankan Windows client.
3. Jalankan Server B attacker khusus skenario serangan.
4. Tunggu semua selesai.
5. Di Server A jalankan:

./scripts/finalize_broker.sh


6. FILE HASIL YANG DIAMBIL
--------------------------

Jika memakai run_experiment.ps1 dari Windows, file hasil otomatis terkumpul.

Lokasi utama:

experiments/<RUN_ID>/mqtt_client.csv
experiments/<RUN_ID>/metadata.env
experiments/<RUN_ID>/raw_flow.csv

Backup hasil Server A:

experiments/<RUN_ID>/server_a_broker/capture.pcapng
experiments/<RUN_ID>/server_a_broker/capture.log
experiments/<RUN_ID>/server_a_broker/raw_flow.csv
experiments/<RUN_ID>/server_a_broker/metadata.env

Backup hasil Server B:

experiments/<RUN_ID>/server_b_attacker/attack.log
experiments/<RUN_ID>/server_b_attacker/controller_attacker.out

Kalau menjalankan tiga terminal manual, file dari Server A dan Server B tetap
perlu disalin sendiri.

7. CATATAN PENTING
------------------

- RUN_ID harus sama dalam satu skenario.
- SCENARIO harus sama dalam satu skenario.
- Jangan menyerang IP selain Ubuntu Server A.
- --yes-local hanya untuk testbed sendiri yang memang diizinkan.
- Kalau nama interface bukan enp0s8, ganti --iface sesuai hasil ip -br address.
