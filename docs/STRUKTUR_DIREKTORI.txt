STRUKTUR DIREKTORI PROJECT TERBARU
==================================

Project sekarang memakai arsitektur sederhana:

1. Windows
   - client MQTT normal;
   - attacker SYN flood menggunakan Nping;
   - pengumpul hasil eksperimen;
   - analisis hasil.

2. Ubuntu Server A
   - broker MQTT Mosquitto;
   - packet capture;
   - ekstraksi capture menjadi raw_flow.csv;
   - rate limiting.

Ubuntu Server B tidak dibutuhkan lagi untuk mode utama. Folder
03_ubuntu_server_b_attacker tetap disimpan sebagai legacy jika suatu saat ingin
kembali ke mode dua Ubuntu Server.

01_windows_client
-----------------

Folder ini dijalankan pada Windows. Tidak membutuhkan WSL.

Perannya:
- mengirim pesan MQTT normal ke broker;
- menjalankan SYN flood dari Windows menggunakan Nping;
- mengambil file hasil dari Ubuntu Server A;
- menyimpan semua hasil dalam experiments/<RUN_ID>/;
- menjalankan analisis.


02_ubuntu_server_a_broker
-------------------------

Folder ini dijalankan pada Ubuntu Server A.

Perannya:
- menjalankan broker MQTT Mosquitto;
- melakukan packet capture langsung pada interface broker;
- membuat raw_flow.csv dari capture.pcapng;
- menerapkan rate limiting pada skenario mitigasi.


03_ubuntu_server_b_attacker
---------------------------

Folder ini adalah folder legacy. Pada konsep terbaru, folder ini tidak perlu
dicopy atau dijalankan di laptop teman.


KENAPA LEBIH SEDERHANA?
-----------------------

Karena hanya ada dua lingkungan yang harus dipahami:

1. Windows sebagai perangkat penguji.
2. Ubuntu Server A sebagai server broker yang diamati.

Dengan begitu, pengujian tetap valid karena serangan masih berasal dari luar
server broker, tetapi setup tidak lagi membutuhkan dua VM Ubuntu.
