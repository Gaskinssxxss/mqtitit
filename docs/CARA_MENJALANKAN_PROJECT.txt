CARA MENJALANKAN PROJECT KONSEP LAMA
====================================

Konsep lama menggunakan PC A sebagai host monitoring.

PC A menjalankan:

- sniffer_capture.sh untuk capture trafik MQTT;
- mqtt_prober.sh untuk membuat trafik MQTT normal;
- run_all.sh untuk menjalankan sniffer dan prober bersamaan.

Broker MQTT berada pada server target.
Attacker berada pada mesin lain dan hanya dijalankan pada skenario DoS.


1. INSTALL DEPENDENCY DI PC A
-----------------------------

sudo apt update
sudo apt install -y tshark mosquitto-clients python3 python3-pip
python3 -m pip install -r requirements.txt


2. CEK KONFIGURASI
------------------

Buka file:

lab_env.sh

Pastikan nilai berikut sesuai:

TARGET_IP
    IP broker MQTT.

MQTT_PORTS
    Port broker MQTT. Contoh: 1883.

NET_IFACE
    Interface jaringan PC A yang akan dicapture.

Contoh isi:

TARGET_IP=192.168.100.50
MQTT_PORTS=1883
NET_IFACE=eth0


3. JALANKAN MODE INTERAKTIF
---------------------------

Gunakan:

./run_all_cli.sh

Isi:

- IP broker MQTT;
- interface jaringan PC A;
- port MQTT.

Setelah dikonfirmasi, script akan menjalankan sniffer dan prober.


4. JALANKAN SKENARIO NORMAL
---------------------------

Pada skenario normal:

1. Broker MQTT berjalan.
2. PC A menjalankan run_all_cli.sh.
3. Attacker tidak dijalankan.
4. Prober mengirim pesan MQTT normal.
5. Sniffer menangkap trafik MQTT yang terlihat pada interface PC A.

Untuk menghentikan eksperimen:

Tekan CTRL+C.

Setelah CTRL+C, run_all.sh akan mencari file pcap terbaru dan menjalankan
extract_raw_flow.sh.


5. JALANKAN SKENARIO DOS
------------------------

Pada skenario DoS:

1. Broker MQTT berjalan.
2. PC A menjalankan run_all_cli.sh.
3. Mesin attacker mengirim serangan ke broker.
4. Prober tetap mengirim pesan MQTT normal.
5. Sniffer menangkap trafik MQTT yang terlihat pada interface PC A.

Catatan:
Pastikan serangan hanya dijalankan pada testbed yang diizinkan.


6. JALANKAN SKENARIO DOS DENGAN RATE LIMITING
---------------------------------------------

Pada skenario DoS + rate limiting:

1. Rate limiting diterapkan pada server broker atau perangkat jaringan yang
   memang menjadi tempat mitigasi.
2. PC A menjalankan run_all_cli.sh.
3. Mesin attacker mengirim serangan ke broker.
4. Prober tetap mengirim pesan MQTT normal.
5. Sniffer menangkap trafik MQTT yang terlihat.


7. HITUNG METRIK
----------------

Setelah file raw_flow.csv terbentuk, jalankan:

python3 compile.py pcap/NAMA_FILE_raw_flow.csv -o metrics.csv --ports 1883

Contoh:

python3 compile.py pcap/mqtt_traffic_20260814_203000_raw_flow.csv -o metrics.csv --ports 1883


8. OUTPUT
---------

Folder hasil:

logs/
    Berisi log prober MQTT.

pcap/
    Berisi file capture pcapng dan raw_flow.csv.

metrics.csv
    Hasil metrik dari compile.py.


9. CATATAN VALIDITAS
--------------------

Karena capture dilakukan pada PC A, data serangan hanya lengkap jika trafik
attacker ke broker melewati interface PC A.

Jika attacker mengirim trafik langsung ke broker tanpa melewati PC A, maka
sniffer di PC A bisa tidak melihat trafik serangan secara lengkap.
