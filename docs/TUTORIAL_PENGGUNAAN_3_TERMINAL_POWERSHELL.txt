TUTORIAL KONSEP LAMA: SNIFFER + PROBER
======================================

Dokumen ini menggantikan tutorial 3 terminal/1 Ubuntu Server.

Konsep yang dipakai sekarang:

PC A:
- sniffer;
- prober;
- ekstraksi data;
- analisis metrik.

Broker MQTT:
- target layanan MQTT.

Attacker:
- mesin lain yang mengirim trafik serangan pada skenario DoS.


1. SIAPKAN PC A
---------------

Install dependency:

sudo apt update
sudo apt install -y tshark mosquitto-clients python3 python3-pip
python3 -m pip install -r requirements.txt

Pastikan script bisa dijalankan:

chmod +x *.sh


2. TENTUKAN IP BROKER DAN INTERFACE
-----------------------------------

Cek interface PC A:

ip -br address

Tentukan:

- IP broker MQTT;
- interface yang akan dicapture;
- port MQTT.

Contoh:

IP broker: 192.168.100.50
Interface: eth0
Port MQTT: 1883


3. JALANKAN EKSPERIMEN
----------------------

Gunakan mode interaktif:

./run_all_cli.sh

Isi nilai yang diminta:

- TARGET_IP;
- NET_IFACE;
- MQTT_PORTS.

Setelah dikonfirmasi, sniffer dan prober akan berjalan.


4. SKENARIO NORMAL
------------------

Untuk normal:

1. Jalankan broker MQTT.
2. Jalankan ./run_all_cli.sh di PC A.
3. Jangan jalankan attacker.
4. Tunggu sesuai durasi pengamatan.
5. Tekan CTRL+C.


5. SKENARIO DOS
---------------

Untuk DoS:

1. Jalankan broker MQTT.
2. Jalankan ./run_all_cli.sh di PC A.
3. Jalankan serangan dari mesin attacker menuju broker.
4. Prober tetap mengirim trafik MQTT normal.
5. Tekan CTRL+C setelah durasi pengamatan selesai.


6. SKENARIO DOS + RATE LIMITING
-------------------------------

Untuk DoS + rate limiting:

1. Aktifkan rate limiting pada sisi broker/perangkat mitigasi.
2. Jalankan ./run_all_cli.sh di PC A.
3. Jalankan serangan dari mesin attacker menuju broker.
4. Tekan CTRL+C setelah durasi pengamatan selesai.


7. SETELAH EKSPERIMEN
---------------------

Setelah CTRL+C, run_all.sh akan otomatis mencoba membuat raw_flow.csv.

Jika perlu ekstrak manual:

./extract_raw_flow.sh pcap/NAMA_FILE.pcapng

Hitung metrik:

python3 compile.py pcap/NAMA_FILE_raw_flow.csv -o metrics.csv --ports 1883


8. OUTPUT
---------

File utama:

logs/mqtt_1883_probe_log.csv
pcap/mqtt_traffic_<timestamp>.pcapng
pcap/mqtt_traffic_<timestamp>_raw_flow.csv
metrics.csv


9. CATATAN VALIDITAS
--------------------

Pada konsep lama, capture tidak dilakukan langsung pada broker. Capture
dilakukan pada PC A. Karena itu, hasil capture hanya valid untuk trafik yang
memang terlihat pada interface PC A.
