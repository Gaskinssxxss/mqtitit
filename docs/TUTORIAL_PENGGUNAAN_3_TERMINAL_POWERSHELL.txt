TUTORIAL PENGGUNAAN PROJECT DENGAN 1 UBUNTU SERVER + WINDOWS
============================================================

Tujuan tutorial ini:
- Menjalankan pengujian dari laptop Windows.
- Ubuntu Server A dipakai sebagai broker MQTT, packet capture, ekstraksi data,
  dan rate limiting.
- Windows dipakai sebagai client MQTT, attacker SYN flood, dan tempat
  mengumpulkan hasil.

Dengan konsep ini, Ubuntu Server B tidak dipakai lagi.


CONTOH ALAMAT
-------------

Ubuntu Server A / Broker : 192.168.56.10
Windows                 : 192.168.56.1
Port MQTT               : 1883
Interface broker        : enp0s8

Kalau IP atau interface berbeda, sesuaikan command.


1. BUKA VIRTUALBOX
------------------

1. Buka VirtualBox.
2. Jalankan VM Ubuntu Server A.
3. Tidak perlu menjalankan Ubuntu Server B.
4. Pastikan Ubuntu Server A sudah bisa di-SSH dari Windows.

Login Ubuntu Server A jika diperlukan:

username: server-a
password: isi password Ubuntu Server A


2. BUKA 2 POWERSHELL DI WINDOWS
-------------------------------

Buka 2 jendela PowerShell.

PowerShell 1:
Windows client, Windows attacker, dan collect hasil.

PowerShell 2:
SSH ke Ubuntu Server A.

Untuk PowerShell 1, lebih aman klik kanan PowerShell lalu pilih
"Run as administrator", karena Nping/Npcap biasanya butuh hak administrator.


3. PERSIAPAN POWERSHELL 1 - WINDOWS
-----------------------------------

Di PowerShell 1, ketik command berikut untuk masuk ke folder Windows:

cd D:\mqtitit\01_windows_client

Kalau baru pull update:

git pull origin main

Install dependency Python jika belum pernah:

py -3 -m pip install -r requirements.txt

Install tool attacker Windows:

1. Install Nmap for Windows.
2. Saat instalasi, aktifkan/install Npcap.
3. Setelah selesai, tutup PowerShell lalu buka lagi sebagai Administrator.

Cek kesiapan Windows:

powershell -ExecutionPolicy Bypass -File .\doctor.ps1

Doctor harus menunjukkan:
- Python tersedia.
- Broker dapat diakses jika broker sudah hidup.
- Nping tersedia jika Windows akan dipakai sebagai attacker.


4. PERSIAPAN POWERSHELL 2 - UBUNTU SERVER A
-------------------------------------------

Di PowerShell 2, ketik command berikut untuk SSH ke Ubuntu Server A:

ssh server-a@192.168.56.10

Masukkan password Ubuntu Server A.

Setelah berhasil login, ketik command berikut:

cd ~/mqtitit
git pull origin main
cd 02_ubuntu_server_a_broker
chmod +x scripts/*.sh

Cek tool Server A:

./scripts/doctor.sh

Pastikan Mosquitto aktif:

sudo systemctl status mosquitto

Kalau belum aktif:

sudo systemctl enable --now mosquitto

Cek interface jaringan:

ip -br address

Cari interface yang memiliki IP broker, misalnya 192.168.56.10.
Contoh interface yang sering muncul:

enp0s8


5. SKENARIO NORMAL
------------------

RUN_ID contoh:

normal_01

PowerShell 2 / Ubuntu Server A:

./scripts/run_broker.sh --scenario normal --run-id normal_01 --broker-host 192.168.56.10 --iface enp0s8 --duration 60 --capture-duration 75

Setelah capture Server A berjalan, pindah ke PowerShell 1 / Windows:

powershell -ExecutionPolicy Bypass -File .\run_client.ps1 -Scenario normal -RunId normal_01 -BrokerHost 192.168.56.10 -Duration 60

Tunggu sampai client Windows selesai dan capture Server A selesai.

Setelah capture selesai, di PowerShell 2 / Ubuntu Server A jalankan:

RUN_ID=normal_01 ./scripts/finalize_broker.sh

Kalau muncul masalah permission pada capture.pcapng, jalankan:

sudo chown -R server-a:server-a experiments/normal_01
chmod 644 experiments/normal_01/capture.pcapng
RUN_ID=normal_01 ./scripts/finalize_broker.sh

Lalu ambil hasil dari PowerShell 1 / Windows:

powershell -ExecutionPolicy Bypass -File .\collect_results.ps1 -RunId normal_01 -ServerAUser server-a


6. SKENARIO SYN FLOOD
---------------------

RUN_ID contoh:

attack_01

PowerShell 2 / Ubuntu Server A:

./scripts/run_broker.sh --scenario syn_flood --run-id attack_01 --broker-host 192.168.56.10 --iface enp0s8 --duration 60 --capture-duration 75

Setelah capture Server A berjalan, pindah ke PowerShell 1 / Windows dan jalankan attacker:

powershell -ExecutionPolicy Bypass -File .\run_attacker.ps1 -Scenario syn_flood -RunId attack_01 -BrokerHost 192.168.56.10 -Duration 60 -AttackRate 1000 -YesLocal -Background

Setelah attacker berjalan di background, langsung jalankan client:

powershell -ExecutionPolicy Bypass -File .\run_client.ps1 -Scenario syn_flood -RunId attack_01 -BrokerHost 192.168.56.10 -Duration 60

Tunggu sampai:
- attacker Windows selesai,
- client Windows selesai,
- capture Server A selesai.

Setelah capture selesai, di PowerShell 2 / Ubuntu Server A jalankan:

RUN_ID=attack_01 ./scripts/finalize_broker.sh

Lalu ambil hasil dari PowerShell 1 / Windows:

powershell -ExecutionPolicy Bypass -File .\collect_results.ps1 -RunId attack_01 -ServerAUser server-a


7. SKENARIO SYN FLOOD DENGAN RATE LIMITING
------------------------------------------

RUN_ID contoh:

mitigation_01

PowerShell 2 / Ubuntu Server A:

./scripts/run_broker.sh --scenario syn_flood_rate_limit --run-id mitigation_01 --broker-host 192.168.56.10 --iface enp0s8 --duration 60 --capture-duration 75

Pada skenario ini, Server A akan meminta password sudo karena rate limiting aktif.

Setelah capture Server A berjalan, pindah ke PowerShell 1 / Windows dan jalankan attacker:

powershell -ExecutionPolicy Bypass -File .\run_attacker.ps1 -Scenario syn_flood_rate_limit -RunId mitigation_01 -BrokerHost 192.168.56.10 -Duration 60 -AttackRate 1000 -YesLocal -Background

Setelah attacker berjalan di background, langsung jalankan client:

powershell -ExecutionPolicy Bypass -File .\run_client.ps1 -Scenario syn_flood_rate_limit -RunId mitigation_01 -BrokerHost 192.168.56.10 -Duration 60

Tunggu sampai semua selesai.

Setelah capture selesai, di PowerShell 2 / Ubuntu Server A jalankan:

RUN_ID=mitigation_01 ./scripts/finalize_broker.sh

Lalu ambil hasil dari PowerShell 1 / Windows:

powershell -ExecutionPolicy Bypass -File .\collect_results.ps1 -RunId mitigation_01 -ServerAUser server-a


8. LOKASI HASIL DI WINDOWS
--------------------------

Semua hasil akan terkumpul di:

D:\mqtitit\01_windows_client\experiments\<RUN_ID>\

Isi penting:

mqtt_client.csv
metadata.env
raw_flow.csv
server_a_broker\capture.pcapng
server_a_broker\capture.log
server_a_broker\metadata.env
server_a_broker\raw_flow.csv

Untuk skenario serangan, ada tambahan:

attack.log
windows_attacker\attack.log


9. CATATAN PENTING
------------------

- RUN_ID harus sama antara Windows dan Ubuntu Server A.
- Jangan pakai RUN_ID yang sama untuk pengujian baru.
- Untuk skenario normal, tidak perlu menjalankan run_attacker.ps1.
- Untuk skenario serangan, Windows berperan sebagai client MQTT dan attacker.
- Serangan hanya boleh diarahkan ke broker uji sendiri atau sistem yang sudah
  mendapat izin.
- Jika raw_flow.csv belum ada, berarti finalize_broker.sh belum berhasil.
- Jika Nping tidak ditemukan, install Nmap dan Npcap di Windows.
